# Typed application API and Boost.Endian

Application handlers consume Heartbeat and ShoppingCart directly. A new message_channel.hpp contains IMessageSender, MessageSenderPtr, and MessageEvents, depending only on the standard library and message types. IMessageSender has virtual send(const Heartbeat&), send(const ShoppingCart&), close(), and is_open(). Send returns true when queued, false for a closed connection or transport limits. Encoding allocation/length failures remain exceptions.

MessageEvents has named on_connected(MessageSenderPtr), on_heartbeat(MessageSenderPtr, const Heartbeat&), on_shopping_cart(MessageSenderPtr, const ShoppingCart&), on_disconnected(MessageSenderPtr, std::error_code), and on_error(std::string_view, std::error_code) callbacks. Message references last for the callback; applications may copy them. TcpEvents aliases this interface. Application code can mock the sender and use MessageEvents without including TCP or Boost headers. Bootstrap code constructs TcpClient/TcpServer and owns io_context as before.

Keep the existing byte-buffer observer as RawTcpEvents. TCP constructors accept either observer contract. An internal adapter owns only a weak reference to the application's typed events and is strongly retained by the client/server state. This keeps the adapter alive during callback-driven public-object destruction, including explicit stop and accept-error shutdown. Raw observers remain weakly held. Connection ownership and cancellation remain unchanged. TcpConnection implements IMessageSender and retains its raw DataBuffer send overload for low-level users. Each typed send encodes and checksums inside the library. Each typed receive decodes and validates before dispatch. Invalid packets close the connection with protocol_error and never reach a message callback. Callback exceptions are still forbidden; catch decoder exceptions separately from invoking callbacks.

Use Boost.Endian endian_store/endian_load for DataBuffer integer operations and the TCP frame length. Float encoding continues through bit_cast<uint32_t>. Protocol buffers and TCP frames are always big-endian; received encoded buffers remain in network order, while decoded numeric values are normal host values. DataBuffer retains explicit little-endian operations for independent buffer use. boost-endian is an explicit private dependency. Preserve exact existing wire fixtures and CRCs.

Tests cover both callbacks over real TCP, typed sending through the interface, raw wire bytes in both directions, invalid CRC and CRC-valid malformed payload rejection, weak observer lifetime and callback-driven shutdown, mockable application logic with no TCP dependency, and existing raw transport/codec behavior. Update all examples and README to prefer the typed interface. Keep the command-line text argument as a Heartbeat login string for the echo example.
