# Invalid message logging and recovery

Typed receivers log invalid data and remain connected. Keep the current four-byte frame length followed by TCPMSG01 header, payload, and CRC. Recover alignment using the existing magic number and only accept a complete candidate with known type, bounded length, valid CRC, and valid payload. Corrupt outer frame lengths can be repaired from a validated message header. During recovery, inspect later candidates even when an earlier damaged header advertises an incomplete body. Retain incomplete candidates and partial magic across reads. Bound receive buffering to the configured message limit plus a fixed read chunk. Network failures and explicit application close still terminate connections. RawTcpEvents continues its custom-protocol framing behavior.

Add MessageErrorCode, MessageErrorDetails (category, field offset within the message or frame prefix, description, optional expected/actual numeric values, received size, connection ID, and stream offset), and MessageDecodeError deriving from std::invalid_argument. Preserve existing codec exception compatibility. Report invalid size, CRC, magic, type, payload length, truncated fields, login length, item count, trailing payload, and framing/recovery errors separately. Verify CRC before delivering decoded message fields.

IMessageErrorLogger::log(const MessageErrorDetails&) is noexcept and transport independent. Inject a shared logger through TcpOptions. The default implementation appends structured records to logs/tcp_helper_errors.log with spdlog and flushes errors. A factory accepts a custom file path. Tests supply capturing/mocked loggers through the same interface. Logging must not escape an asynchronous callback. Document file creation failures at logger setup and stderr fallback for runtime logging failure.

Separate an internal MessageStreamDecoder from sockets so unit tests can feed corrupted/fragmented streams directly. It validates and returns DecodedMessage values; ConnectionState dispatches them through TypedEventsAdapter without repeating decoding. ClientState/ServerState retain the typed adapter; application observers remain weak. Retain Allman style, named class callbacks, network byte order, and the existing single-io_context-thread contract.

Tests cover all replacement byte values at every position of both known packets, bit errors and bursts, insertion/deletion/truncation/appending, CRC-valid malformed headers/payloads with precise diagnostics, corrupt frame lengths, garbage, false/partial magic, incomplete misleading candidates, bounded buffering, logger file output, and recovery of valid messages on the same TCP connection at both client and server. Finite mutation coverage does not imply detection of every possible multi-byte CRC collision.
